`ConsumeOptions` controls the behaviour of message consumption in Broccoli Queue. It is accepted by [`consume`](/api/broccoli-queue#consume), [`consume_batch`](/api/broccoli-queue#consume_batch), [`try_consume`](/api/broccoli-queue#try_consume), [`try_consume_batch`](/api/broccoli-queue#try_consume_batch), [`process_messages`](/api/broccoli-queue#process_messages), and [`process_messages_with_handlers`](/api/broccoli-queue#process_messages_with_handlers). Pass `None` for any of these to use the documented defaults.

## Struct Fields

```rust
#[derive(Debug, Clone)]
pub struct ConsumeOptions {
    pub auto_ack: Option<bool>,
    pub fairness: Option<bool>,
    pub consume_wait: Option<std::time::Duration>,
    pub handler_ack: Option<bool>,
}
```

<ResponseField name="auto_ack" type="Option<bool>">
  When `Some(true)`, the broker automatically acknowledges the message as soon as it is consumed — no explicit call to `acknowledge` is needed. Calling `acknowledge` or `reject` on an auto-acknowledged message will return an error. Default: `Some(false)`.
</ResponseField>

<ResponseField name="fairness" type="Option<bool>">
  When `Some(true)`, messages are consumed from fairness sub-queues in a round-robin fashion, ensuring no single producer's messages starve others. **Redis broker only.** Default: `None` (disabled).
</ResponseField>

<ResponseField name="consume_wait" type="Option<std::time::Duration>">
  Sleep duration inserted between iterations of tight consumer loops. Because CPU-bound loops cannot be interrupted by Tokio, a small sleep — even `Duration::ZERO` — yields to the executor and allows tasks spawned via `tokio::spawn` to be cancelled. Default: `None` (zero wait).
</ResponseField>

<ResponseField name="handler_ack" type="Option<bool>">
  When `Some(false)`, `process_messages` and `process_messages_with_handlers` skip the automatic `acknowledge` call after a handler returns `Ok`. Useful when the handler spawns a long-running background task and returns immediately — acknowledgement is then delegated to a separate actor or reaper process. **Note:** on handler error, `reject` is always called regardless of this setting. Default: `Some(true)`.
</ResponseField>

## Default Values

`ConsumeOptions::default()` returns:

| Field           | Default value  |
| --------------- | -------------- |
| `auto_ack`      | `Some(false)`  |
| `fairness`      | `None`         |
| `consume_wait`  | `None`         |
| `handler_ack`   | `Some(true)`   |

```rust
use broccoli_queue::queue::ConsumeOptions;

// Explicitly construct the defaults
let opts = ConsumeOptions::default();
assert_eq!(opts.auto_ack, Some(false));
assert_eq!(opts.handler_ack, Some(true));
assert!(opts.fairness.is_none());
assert!(opts.consume_wait.is_none());
```

## ConsumeOptionsBuilder

The preferred way to construct `ConsumeOptions` is through the builder, created with `ConsumeOptions::builder()`. All methods are `const fn` and `#[must_use]`.

### `ConsumeOptions::builder`

```rust
pub const fn builder() -> ConsumeOptionsBuilder
```

Returns a new `ConsumeOptionsBuilder` with all fields unset.

### `.auto_ack`

```rust
pub const fn auto_ack(mut self, auto_ack: bool) -> Self
```

<ParamField path="auto_ack" type="bool" required>
  Set to `true` to have the broker acknowledge messages automatically upon consumption. When enabled, do not call `acknowledge` or `reject` manually.
</ParamField>

### `.fairness`

```rust
pub const fn fairness(mut self, fairness: bool) -> Self
```

<ParamField path="fairness" type="bool" required>
  Set to `true` to consume from fairness sub-queues in round-robin order. Redis broker only.
</ParamField>

### `.consume_wait`

```rust
pub const fn consume_wait(mut self, consume_wait: std::time::Duration) -> Self
```

<ParamField path="consume_wait" type="std::time::Duration" required>
  Duration to sleep between consumer loop iterations. A value of `Duration::ZERO` is sufficient to allow Tokio task cancellation; larger values reduce CPU usage at the cost of slightly higher latency.
</ParamField>

### `.handler_ack`

```rust
pub const fn handler_ack(mut self, followup: bool) -> Self
```

<ParamField path="followup" type="bool" required>
  Set to `false` to prevent `process_messages` / `process_messages_with_handlers` from auto-acknowledging after a successful handler. The message remains in the processing queue until another actor acknowledges or rejects it.
</ParamField>

### `.build`

```rust
pub const fn build(self) -> ConsumeOptions
```

Consumes the builder and returns the configured `ConsumeOptions`.

## Code Examples

### Auto-acknowledge on consume

The message is removed from the queue the moment it is delivered. No further lifecycle calls are needed (or permitted).

```rust
use broccoli_queue::queue::ConsumeOptions;

let opts = ConsumeOptions::builder()
    .auto_ack(true)
    .build();

let msg: BrokerMessage<Order> = queue.consume("orders", Some(opts)).await?;
// Do NOT call queue.acknowledge(…) here — it will return an error.
println!("Auto-acked order: {}", msg.payload.id);
```

### Fairness queue consumption

Round-robin across all disambiguator sub-queues so that no single producer's messages are prioritised over others (Redis only).

```rust
use broccoli_queue::queue::ConsumeOptions;

let opts = ConsumeOptions::builder()
    .fairness(true)
    .build();

let msg: BrokerMessage<Order> = queue.consume("orders", Some(opts)).await?;
queue.acknowledge("orders", msg).await?;
```

### Allow task cancellation via `consume_wait`

A 10 ms sleep is inserted between loop iterations, giving Tokio an opportunity to abort the task handle returned by `tokio::spawn`.

```rust
use broccoli_queue::queue::ConsumeOptions;

let opts = ConsumeOptions::builder()
    .consume_wait(std::time::Duration::from_millis(10))
    .build();

let handle = tokio::spawn({
    let queue = queue.clone();
    async move {
        queue
            .process_messages("jobs", Some(4), Some(opts), |msg| async move {
                // … handle msg …
                Ok(())
            })
            .await
    }
});

// Later — the sleep in the loop allows this to take effect promptly.
handle.abort();
```

### Skip auto-acknowledge after handler (manual ack delegation)

The handler spawns a background task and returns immediately. Acknowledging the message is left to the spawned task, keeping it in the processing queue until the real work is done.

```rust
use broccoli_queue::queue::ConsumeOptions;

let opts = ConsumeOptions::builder()
    .handler_ack(false)
    .build();

queue
    .process_messages(
        "jobs",
        Some(4),
        Some(opts),
        |msg: BrokerMessage<JobPayload>| {
            let queue = queue.clone();
            async move {
                tokio::spawn(async move {
                    // Long-running work …
                    queue.acknowledge("jobs", msg).await.ok();
                });
                // Return immediately — message stays in processing queue
                // until the spawned task calls acknowledge.
                Ok(())
            }
        },
    )
    .await?;
```

<Note>
  When `handler_ack(false)` is set and the handler returns `Err(_)`, `process_messages` **still calls `reject`** immediately. The `handler_ack` setting only affects the success path.
</Note>

### Combine options

```rust
use broccoli_queue::queue::ConsumeOptions;

let opts = ConsumeOptions::builder()
    .fairness(true)
    .consume_wait(std::time::Duration::from_millis(5))
    .build();

queue.process_messages("jobs", Some(8), Some(opts), handler).await?;
```

---

<Tip>
  For most workloads, passing `None` for `consume_options` in `process_messages` is fine. Add `consume_wait` only if you need reliable task cancellation, and `handler_ack(false)` only when your handler explicitly delegates the acknowledge step.
</Tip>
